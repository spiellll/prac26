# Ритм — дневник тренировок

Проект учебной практики Афанасьева Афанасия Егоровича, ИИ-ПМИ-23.
Направление — прикладная математика и информатика, профиль — искусственный интеллект.

Сайт сохраняет тренировки, подходы, рабочий вес, массу тела, сон, питание и
свободные заметки. Он показывает карту записанной нагрузки, графики и
последовательный цикл тренировок. Это развитие исходного дневника `afanasev1`.

Интерфейс: **React и TypeScript**. Сервер практики: **Python, Flask,
SQLAlchemy**. Локальное хранилище: **SQLite**. Формат API: **JSON**.
Для учебного задания выбран Flask; Django параллельно не нужен.

## Запуск привычного сайта с Python API

Требуются Python 3.9+ и Node.js 22.13+; рекомендуем Node.js 24 LTS.
Откройте папку `afanasev1` в VS Code. Один раз выполните:

```sh
npm ci
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements-dev.txt
npm run build:practice
```

Затем:

```sh
npm run practice
```

Откройте **http://127.0.0.1:5001/**. Остановка — **Ctrl+C**.
Можно также дважды открыть `start-practice.command` после установки зависимостей.
Для разработки с автоматическим обновлением интерфейса: `npm run dev:practice`,
затем http://127.0.0.1:5173/. Flask API в этом режиме работает на порту 5001.
Если порт занят другим проектом, сначала остановите его через Ctrl+C.

После сборки для обычного запуска достаточно одного Python-процесса:

```sh
.venv/bin/python -m flask --app backend.wsgi:app run --port 5001
```

`/api/v1/health` — служебный JSON-ответ о состоянии. Сам сайт открывается по `/`.
Для Run and Debug в VS Code выберите «Ритм — Flask API и сайт»; сначала
выполните сборку интерфейса.

## Прежние записи и перенос

Flask использует тот же файл **`data/diary.sqlite`** и прежние четыре таблицы.
Переносить записи вручную или импортировать их из ChatGPT не нужно.
Нормализация старого формата упражнений применяется при чтении, без
перезаписи сохранённых записей. Резервная копия перед добавлением Flask
находится локально в `data/backups/`.

Для переноса остановите приложение и скопируйте всю папку с `data`.
На втором компьютере установите зависимости командами выше: `node_modules`
и `.venv` нужно создавать заново для его системы. После этого `npm run practice`
откроет прежний дневник, и новые записи будут сохраняться в той же базе.
История чата не является базой приложения.

Прежний Node.js-запуск `npm run dev` сохранён. Новая версия практики запускается
через `npm run practice`; оба варианта используют один локальный дневник,
поэтому запускайте один из них. Старые инструкции сохранены в
[practice/LEGACY_NODE.md](practice/LEGACY_NODE.md).

## API и учебная задача

Тренировочная запись — специализированная заметка. Через API можно создать,
прочитать, изменить, удалить и восстановить её. Существующий интерфейс
работает через совместимый `/api/diary`, который теперь обслуживает Flask.
Ресурсный REST API доступен отдельно для изучения и Postman:

| Метод | Адрес | Действие |
|---|---|---|
| GET | `/api/v1/health` | Состояние сервера и базы |
| GET, POST | `/api/v1/entries` | Список с фильтрами и создание |
| GET, PATCH, DELETE | `/api/v1/entries/{id}` | Чтение, изменение, мягкое удаление |
| POST | `/api/v1/entries/{id}/restore` | Отмена удаления |
| GET, PUT | `/api/v1/profile` | Настройки профиля |
| GET | `/api/v1/messages` | История вопросов |
| GET | `/api/v1/stats` | Статистика с ORM JOIN |

```sh
curl http://127.0.0.1:5001/api/v1/health
curl 'http://127.0.0.1:5001/api/v1/entries?kind=workout&page=1&per_page=5'
curl -X POST http://127.0.0.1:5001/api/v1/entries \
  -H 'Content-Type: application/json' \
  -d '{"kind":"note","title":"Самочувствие","text":"После разминки чувствовал себя хорошо"}'
```

Фильтры: `kind`, `q`, `from`, `to`; пагинация: `page`, `per_page` (до 100).
API возвращает статусы 200/201/204 и ошибки 400/403/404/409/413.
Для сайта и API с одного адреса CORS не требуется; запись с чужого Origin
отклоняется. Подробное сопоставление с заданием:
[practice/requirements-map.md](practice/requirements-map.md).
Примеры запросов: [practice/api.http](practice/api.http) и
[коллекция Postman](practice/ritm.postman_collection.json).

SQLite хранит данные, JSON задаёт вид запросов и ответов. SQLAlchemy
отображает существующие таблицы `profiles`, `entries`, `messages`, `advice`.
Связь записей с профилем задаётся по `user_id` без изменения старой схемы.
Примеры SQL, включая JOIN: [practice/sql_examples.sql](practice/sql_examples.sql).

## Проверки и обработчик логов

Все Python-тесты используют временные базы:

```sh
.venv/bin/python -m pytest -c backend/pytest.ini backend/tests log_tools -q
.venv/bin/python -m pip freeze
node scripts/check-domain.mjs
node scripts/check-plans.mjs
node scripts/check-progress.mjs
npm run build:practice
```

Результат `pip freeze` установленного окружения сохранён в
`backend/requirements-lock.txt`. Старый `scripts/check-api.mjs` предназначен
для прежнего Node API и изменяет живую базу; для практики используются
изолированные pytest-тесты.

Мини-проект первого этапа:

```sh
.venv/bin/python -m log_tools.process_logs log_tools/sample.log --strict
```

Обработчик читает файл журнала, разбирает записи и сравнивает подсчёт
вложенными циклами O(n × m) с Counter O(n). Используются функции,
dataclass, списки и словари; результат выдаётся в JSON.

## Docker и внешний хостинг

```sh
docker compose up --build -d
docker compose logs -f
docker compose down
```

Локальный Docker-сайт: **http://127.0.0.1:5174/**. SQLite подключается из
папки `data`, поэтому остановка контейнера сохраняет записи.
Dockerfile собирает React и запускает Flask через Gunicorn.

Для Render подготовлен `render.yaml`: публичное демо и отдельная PostgreSQL
для хранения между перезапусками. Личные записи, `.env` и `.dev.vars`
не входят в Git и Docker-образ. У каждого посетителя демо отдельная
подписанная сессия. Экспорт JSON позволяет сохранить свой дневник;
очистка cookie создаст новую сессию, это не система аккаунтов.

На бесплатном Render нет постоянного диска для SQLite, а бесплатная
PostgreSQL имеет срок 30 дней. Поэтому бесплатный вариант рассчитан
на короткую защиту; для постоянного хранения выберите подходящий тариф
или другой сервер. Инструкции Render, VPS, nginx, screen и DBeaver:
[practice/DEPLOYMENT.md](practice/DEPLOYMENT.md).

**Работающее демо:** [ritm-practice.onrender.com](https://ritm-practice.onrender.com/).
Проверка API и подключения к PostgreSQL:
[/api/v1/health](https://ritm-practice.onrender.com/api/v1/health).
Опубликовано и проверено 3 ноября 2026 года из ветки `ritm-fitness-practice`.
Подтверждены Docker-сборка на Render, CRUD и изоляция дневников посетителей.
После простоя бесплатный сервер может открываться около минуты.

## Возможности дневника

- Привычные тёмный интерфейс, карта тела с бицепсом и предплечьями, графики.
- Четыре плана по очереди: сила и руки, спина, ноги, грудь/трицепс/плечи.
- Отдельные подходы с весом, повторениями, тяжестью и отметкой разминки.
- Вес тела, сон, питание, самочувствие, отдых и произвольные заметки.
- Цикл структурированных вопросов и локальные наблюдения без внешнего ИИ.
- Условный индекс нагрузки со спадом за 14 дней; он не измеряет
  физиологическое восстановление и не предписывает упражнения.
- Мягкое удаление, отмена удаления, JSON-экспорт и локальные напоминания.

Системные уведомления работают при открытой странице; закрытый сайт
не отправляет фоновые Push. Пример данных в интерфейсе не сохраняется
автоматически в дневник.

## Структура

```text

lib/             расчёты нагрузки, планов, веса и прогрессии
frontend/        точка входа для статической сборки
backend/         Flask, ORM, валидация и изолированные pytest-тесты
data/            локальная SQLite и резервные копии, исключены из Git
log_tools/       обработчик логов и его тесты
practice/        учебные материалы, API, SQL и инструкция деплоя
public/          изображения, иконки и PWA
```
