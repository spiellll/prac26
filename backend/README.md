# Python API дневника «Ритм»

Flask и SQLAlchemy работают с теми же четырьмя таблицами SQLite, которые использовал прежний сайт: `profiles`, `entries`, `messages`, `advice`. Вложенные упражнения и подходы остаются JSON внутри текстового поля `data`. JSON — формат обмена и записи вложенных полей; SQLite — база данных. Менять старый файл дневника или переписывать интерфейс для этого не требуется.

## Запуск

Команды выполняются из корня `afanasev1`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
.venv/bin/python -m flask --app backend.wsgi:app run --host 127.0.0.1 --port 5000
```

Сервер слушает `http://127.0.0.1:5001`. Если интерфейс уже собран в `frontend-dist`, он доступен по `/`. Служебный маршрут — `/api/v1/health`.

По умолчанию используется `data/diary.sqlite` относительно корня проекта, независимо от текущей директории терминала. Другой файл задаётся переменной `RITM_DB_FILE`. Папка и пустые таблицы создаются автоматически, существующие строки не перезаписываются. Чтение старых упражнений с `sets: 3` и `group: "back"` преобразует их в нынешний JSON только в ответе API.

Для PostgreSQL можно задать `DATABASE_URL=postgresql://user:password@host/database`. Драйвер `psycopg` указан в зависимостях. Для повседневной локальной работы достаточно SQLite.

## API

| Метод | Маршрут | Результат |
|---|---|---|
| GET | `/api/v1/health` | Проверка сервера и соединения с БД |
| GET | `/api/v1/entries` | `items`, `page`, `per_page`, `total`, `pages` |
| POST | `/api/v1/entries` | Создание, `201` и `{ "entry": … }` |
| GET | `/api/v1/entries/<uuid>` | Одна запись |
| PATCH | `/api/v1/entries/<uuid>` | Частичное изменение записи |
| DELETE | `/api/v1/entries/<uuid>` | Мягкое удаление, `204` |
| POST | `/api/v1/entries/<uuid>/restore` | Восстановление |
| GET, PUT | `/api/v1/profile` | Чтение и сохранение профиля |
| GET | `/api/v1/messages` | История вопросов с пагинацией |
| GET | `/api/v1/stats` | Счётчики типов записей, следующий план |

Фильтры списка: `kind`, `q`, `from`, `to`, `page`, `per_page`. Также поддержаны имена `date_from` и `date_to`. Максимальный размер страницы — 100, тела запроса — 150 000 байт. Поиск учитывает кириллицу и регистр. Даты проверяются как календарные, числовые значения проверяются на диапазоны; `NaN`, бесконечности и логические значения вместо чисел отклоняются.

```sh
curl http://127.0.0.1:5001/api/v1/health
curl 'http://127.0.0.1:5001/api/v1/entries?kind=workout&page=1&per_page=10'
curl -X POST http://127.0.0.1:5001/api/v1/entries \
  -H 'Content-Type: application/json' \
  -d '{"kind":"note","title":"Наблюдение","text":"Сегодня отдохнул"}'
```

В REST `id`, `date`, `createdAt`, `title` и пустые поля создаются по умолчанию, если не переданы. При изменении UUID и исходная дата создания сохраняются. Удаление и восстановление можно безопасно повторить. Повторный POST с существующим UUID возвращает `409`, неизвестный UUID — `404`, неверные данные — `400`.

`GET /api/diary` и `POST /api/diary` сохранены для прежнего интерфейса. Действия: `saveEntry`, `saveProfile`, `deleteEntry`, `restoreEntry`, `chat`, `report`. Диалог вопросов работает локально. Повтор отправки с тем же UUID возвращает прежний ответ без дублирования сообщений. Распознанные упражнения возвращаются как черновик и становятся тренировкой только после сохранения пользователем. Сводка использует даты, количество записей и последовательность цикла. Внешнего ИИ и передачи записей провайдерам нет.

В `models.py` задано ORM-отношение профиля и записей через `user_id`. Маршрут `/stats` выполняет SQL `LEFT JOIN` этого отношения и группировку типов записей. Ограничение по владельцу применяется ко всем ресурсам.

## Публичное демо

```sh
export PUBLIC_DEMO=1
export SECRET_KEY='replace-with-a-long-random-secret'
export RITM_DB_FILE='data/demo.sqlite'
.venv/bin/gunicorn --bind 0.0.0.0:8080 backend.wsgi:app
```

В демо каждый браузер получает отдельного владельца `demo_<uuid>` в подписанной cookie. Прежний локальный владелец `local_seedy` никогда не выбирается в этом режиме. Секрет необходимо задать в настройках хостинга, сохраняя его между перезапусками. На HTTPS задайте `RITM_COOKIE_SECURE=1`. Для постоянного хранения SQLite файл должен находиться на подключённом диске; альтернативно используется PostgreSQL.

Локальный режим сохраняет прежний профиль по умолчанию из сайта, даже если его ещё нет отдельной строкой в таблице `profiles`. Публичный режим использует пустые имя, опыт и предпочтения. Признак `publicDemo` в `/api/diary` позволяет интерфейсу явно подписать режим демонстрации.

API не разрешает межсайтовую запись: заголовок Origin проверяется относительно адреса сервера. При отдельном dev-сервере интерфейса укажите `RITM_ALLOWED_ORIGINS=http://127.0.0.1:5173,http://localhost:5173` или используйте прокси, сохраняющий Host. Для сайта, обслуживаемого самим Flask, дополнительная настройка не нужна.

## Тесты

```sh
cd backend
../.venv/bin/python -m pytest --cov=ritm_api --cov-report=term-missing
```

Из корня эквивалентно: `.venv/bin/python -m pytest -c backend/pytest.ini backend/tests`. Тесты создают собственные базы во временных папках и не открывают личный дневник. Покрыты CRUD, валидация, поиск, диапазоны дат, пагинация, совместимость старых данных, повтор запросов, мягкое удаление, профиль, статистика и изоляция посетителей демо.
